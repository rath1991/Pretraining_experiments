So transformers as we know are usually taught to us was a system with encoder and decoder blocks. Where the encoder processes information and store the rich embeddings containing info of both positional and info from other words in its vicinity and far away, after encode block. Next this is being used by decoder block and one or more inputs fused with encoder representation, start spewing one word after the other. This architecture is what you see in BERT for example. BERT type of models usually learn language understanding through self supervised mask token prediction. On the other hand, we have GPT like models, which doesnt use the encoder block at all, and trains and predicts on the decoder block only. Before we got here, we used to rely on sequence models, such as RNNs, LSTMs. They were and are still really good at remembering sequence but even the sequence length is large and as you back propagate loss in time (as in the hidden states ), there is either vanishing/exploding gradient issue. LSTMs partially solved the issue through their gated mechanisms - each gate accepts hidden state and input and update the cell state (long term memory) and hidden state . Forget gate decides how much of long term memory to forget, input gate decides how much incoming input to keep and then weighted combination of input memory with long term memory is retained . These gates learn their weights through training however still suffer from gradient porblem discussed as we backpropagate across time. 

The SEQ to SEQ model was built on this architecture - here we have encoder decoder RNNs, and and the end of encoder block we have all the info embedded in a context vector block. And using info from this block and incoming token from translated text, we would predict the next token. This suffers from the fact that it loses context retention as context lenght increases, also it doesnt understand how much weight should be put to word several words way from the current word in question because only the terminal hidden state info is used -- information loss . That is where Badanou attention came into being, where now after the encoder block we have a feed forward layer connection that helps to learn the mapping /importance between the current state vs all the states previous to it in time. 

In the attention is all you need, paper, this mechanism of relying on hidden states in seq to seq models were completely removed, focusing rather on self attention. 

Given below would be a step by step approach for building a decoder only GPT block that will encompass the transformer journey. 
1. We start with data processing - here the question remains on how would you group tokens on character level, word level, or subword level. For GPT2, we chose byte pair encoding that combines both character level , and word level, It starts with grouping characters in sequence iteratively unless the pattern breaks. So you will eventually end up with token ids that may include characters as well as longer sub words. 
1. a. We create a training data set with (seq lenght, stride) and target as next word. Repeat the excerise and it becomes a self supervised dataset creation using dataset and dataloaders from pytorch. 
2. Once we generate token IDs with BPEs, we proceed to next step of generating its embeddings. In theory, you can simply generate a word2vec or glove embedding for the same, but for GPT2, we learn the emebddings as we train. So we initialize with arbitrary weight values of 768 dimension and these will get updated during training. 

3. Then we move to generating positional encoding for the tokens, so that we atleast how the tokens are placed say relative to each other. You can use sinusodial positional encoding (used in 2017 bhaswani paper), in this case, we would also want to learn the positional encodings for tokens of fixed sequence lenght say 256, hence they are also initialized. 

4. We add the tokens (seq lenght* n_dim) token embeddings with positional encodings, to arrive at token embedding with encoded situational info. 

Transformer block starts here -- 

5. Next we use a drop out layer to utilize that all neurons are utulized properly by learning some aspect of the nuances in the data. 

6. We do a layer normalization next inorder to prevent gradients from collapsing , as some arbitrarily high weights can lead to improper loss propagation and weight updates. Also, since the input token distribution can change from batch to batch there may be a covariate shift, due to non normalized weights. Mention if we do any special trick during layer notmalization. 

7. Post layer normalization we are ready to pass the inputs throught multi head attention blocks. 
We initialize Key, Query, Value matrices. We may also choose to keep multiple heads say 12 heads are there and token embedding space is 768, so head dim would be 64. The query or the target token under question would be multiplied by keys adjacent tokens, the weight matrices simply project the input token embeddings to relevant dimensions. Then these product becomes self attention scores divided by square root of dimension for numerical stability and then undergoes softmax normalization. The normalizaed attention scores just tell importance of other token on query but there is no way to get a richer vector which combines this info along with the toke under questions own embedding. Thats where context vector arises.  Attention scores gets multiplied with value matrices to give rise to context vector a superposition of effects of other tokens on query. We use a causal attention model, where we mask out the forward tokens in future, then we do the softmax normalization. But question remains when we are doing pre layer normalization, arent we leaking data in the attention block. 

Now when we are splitting into heads essentially we are forcing each head to focus on one aspect of the rich context vectors - it can be subject, tone, verb etc. Post attention block processing all these heads are concatenated back to original dim instead of say 12,64. 
Then we do a residual connection addition where we add the embeddings before attention transformation with what we got post transformation. This ensures the gradient flow is smooth instead of blowing up or diminising across layers. This is followed by layer normalization and dropout before we go to the feedforward layer. 
In feed forward layer, we essentially project the context vector to higher dimension and apply a nonlinear activation (GELU) to learn richer representation about the token embeddings. The sparsity allows us to unpack a lot of details and nuances missed out earlier. This can also act as a compressed knowledge layer say 'the cat sat on the mat', instead of just looking at the contextual understanding. Then project it back to a similar dimension. The GELU activation instead of RELU is a Gaussian Error Linear Unit, x*gausian dist(x), ensures we dont end up with dead neurons as in case of RELU.  The output undergoes another layer of normalization and residual connection addition. And gets processed by downstream transformer blocks 12. 

At the end of the all the blocks, what we end up doing is a softmax on all the tokens following the target token, so you end up with say 50257 * sequence lenght, this tells the probability of next token following the previous token.   

During the training phase, the loss is computed as cross entropy loss or negative likelihoood and is propagated back. So we want to see take neg log likelihood of the probability of the actual target token, initially it can be off, but this get closer to 1 with loss minimization.  We can also look at perplexity, which raises the exponent of cross entropy. A high perplexity value suggest all token are equally likely and vice versa.
